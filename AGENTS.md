# yatmux - LLM Development Guide

This document provides comprehensive guidance for AI agents working on the yatmux project.

## Project Overview

**yatmux** is a terminal emulator written in Rust with tabs, splits, and a themeable UI. It provides a modern terminal multiplexer experience with features like:

- Tabbed interface and split panes
- Themeable system with built-in themes
- Shell integration (OSC 7/133)
- URL detection and click handling
- Search and selection capabilities
- Configuration system with live reload

## Architecture

### Core Modules

```
src/
├── main.rs              # Entry point
├── lib.rs               # Library exports
├── app/                 # Application layer
│   ├── mod.rs           # Main App struct and event handling

│   ├── tab.rs           # Tab management

│   └── winit_handler.rs # Window event handling
├── config/              # Configuration system
│   ├── mod.rs           # Main Config struct
│   ├── config.rs        # Configuration loading
│   ├── theme.rs         # Theme system
│   ├── keybind.rs       # Keybinding system
│   └── builtin_themes.rs # Generated by build.rs
├── core/                # Core functionality

│   ├── selection.rs     # Text selection
│   └── scrollback.rs    # Scrollback buffer
├── renderer/            # Rendering system

│   └── font.rs          # Font handling
├── terminal/            # Terminal emulation

└── pty.rs               # PTY handling
```

### Build System

- **Cargo**: Standard Rust build system
- **build.rs**: Custom build script that generates `builtin_themes.rs` from `themes/` directory
- **Dependencies**: Uses `winit` for windowing, `portable-pty` for PTY, custom `tattoy-wezterm-term` fork

## Configuration System

### Theme Development

- **Location**: `themes/` directory with `.toml` files
- **Build Process**: `build.rs` generates `src/config/builtin_themes.rs`
- **Validation**: Use `scripts/dev/theme-check.sh` to validate themes
- **Testing**: Test themes with `cargo run -- --theme <theme-name>`

### Configuration Loading

- **Priority**: User config > built-in defaults
- **Format**: TOML with optional sections
- **Hot Reload**: `Ctrl+Shift+R` reloads config at runtime
- **Validation**: Config is validated during loading with helpful error messages

## Code Style and Conventions

### Rust Patterns

- **Error Handling**: Use `anyhow::Result` for error propagation
- **Async**: Avoid async unless necessary for PTY operations
- **State Management**: Use structs for state, prefer immutable data
- **Event Loop**: Use `winit` event loop with custom events

### Code Organization

- **Mod Structure**: Each module should have a clear responsibility
- **Public API**: Document public functions with `///` doc comments
- **Dependencies**: Minimize external dependencies, prefer Rust stdlib
- **Testing**: Include unit tests in the same module or `tests/` directory

### Performance Considerations

- **Rendering**: Use efficient drawing primitives in `renderer/painter/`
- **Memory**: Be mindful of large scrollback buffers
- **PTY**: Handle PTY operations asynchronously to avoid blocking
- **Events**: Process events efficiently to maintain responsiveness

## Common Development Tasks

### Adding a New Feature

1. **Understand Requirements**: Read relevant documentation and existing code
2. **Plan Implementation**: Identify affected modules and documentation
3. **Implement Code**: Follow existing patterns and conventions
4. **Add Tests**: Ensure adequate test coverage
5. **Update Documentation**: Update relevant docs/ files
6. **Validate**: Run `make quick-check` and manual testing

### Debugging

- **Logging**: Use `log::debug!()` for debugging output
- **Environment**: Set `RUST_LOG=debug` for verbose logging
- **Backtraces**: Set `RUST_BACKTRACE=1` for error backtraces
- **Development Mode**: Use `scripts/dev/run-dev.sh` for debug builds

### Theme Development

1. **Create Theme File**: Add `.toml` file to `themes/` directory
2. **Validate Theme**: Run `scripts/dev/theme-check.sh`
3. **Test Theme**: Use `cargo run -- --theme <theme-name>`
4. **Update Docs**: Update `docs/themes.md` if adding new theme options
5. **Rebuild**: Run `make build` to regenerate builtin themes
